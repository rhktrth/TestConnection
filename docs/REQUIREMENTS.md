# TestConnection 要件定義

この文書は、TestConnection が満たすべき**現在の要件**を定義します。実現方法、クラス構成、通信 API、テスト方法などの設計・実装詳細はここでは決めません。

要件を具体的な外部仕様へ落とし込む文書は [`EXTERNAL_DESIGN.md`](EXTERNAL_DESIGN.md)、その実現方法を定める文書は [`INTERNAL_DESIGN.md`](INTERNAL_DESIGN.md) を正本とします。

## 1. 目的

### REQ-SCOPE-001: ネットワーク疎通の確認

Windows 端末から、ルーター、ファイアウォール、冗長構成、経路切替などがある環境に対して、指定した送信元・宛先・プロトコルの疎通状態を繰り返し確認できること。

TestConnection は、アプリケーションの正常性確認、負荷試験、パケット解析、経路やファイアウォール規則の自動診断を主目的としない。

## 2. 機能要件

### REQ-PROTOCOL-001: 対象プロトコル

TCP、UDP、DNS、ICMP Echo を用いた疎通確認を実行できること。

プロトコルごとに「疎通できた」と判断する観測点が異なるため、外部設計で成功・失敗の意味を明確にすること。

### REQ-SOURCE-001: 送信元条件

試験時にローカル IP アドレスを指定できること。指定しない場合は、OS の通常の送信元アドレス選択を利用できること。

### REQ-DESTINATION-001: 宛先指定

TCP / UDP / Ping では、IPv4 アドレスまたはホスト名 / FQDN を宛先として指定できること。DNS では問い合わせ先の DNS サーバーを明示できること。

### REQ-REPEAT-001: 複数試験と反復実行

複数の疎通試験を登録し、一定の順序と間隔で繰り返し実行できること。利用者が停止を要求した場合は、実行中の通信を安全に中断して終了できること。

### REQ-SERVER-001: 受信側での確認

TCP / UDP についてはサーバーとして待受でき、クライアント側だけでは確認できない受信側の成立を確認できること。

### REQ-CONFIG-001: 試験設定の保存

試験定義をファイルへ保存し、後から読み込んで再利用できること。既存の TestConnection 設定ファイルとの互換性を維持すること。

### REQ-RESULT-001: 結果の確認

各試行の成功・失敗と接続条件を、利用者が時系列で確認できること。画面表示とファイル出力を利用できること。

### REQ-NIC-001: NIC 設定の一時変更

試験条件として必要な場合、Windows NIC の IP アドレス、サブネットマスク、デフォルトゲートウェイを一時的に変更できること。

### REQ-NIC-002: NIC 設定の復元

TestConnection が変更した NIC 設定は、通常の操作・終了経路で変更前の状態へ復元できること。変更していない NIC 設定まで管理対象へ広げないこと。

## 3. 非機能要件・制約

### REQ-RUNTIME-001: 実行環境

Windows 11 22H2 以降の標準環境で、利用者が TestConnection のためだけに追加の実行環境を導入せず利用できること。

### REQ-DISTRIBUTION-001: 配布

インストーラーを必須とせず、ZIP を展開して実行できること。配布物は個人で把握・保守できる単純な構成に保つこと。

### REQ-MAINTAIN-001: 保守性

将来拡張だけを目的とした抽象化、フレームワーク、互換層、設定項目を増やさず、要件・外部設計・内部設計・実装・テストの対応を人間が追跡できること。

### REQ-TESTABILITY-001: 再現可能な検証

通常の自動テストは外部ホストや実 NIC の偶然の状態へ依存せず、可能な範囲でループバックや純粋なロジックを用いて再現可能に検証できること。実 NIC など、自動化が適切でない要件は手動確認として明示すること。

## 4. 要件から外部設計への対応

要件は「何を満たすか」を定義し、具体的に外部から観測できる仕様は `EXTERNAL_DESIGN.md` で定義します。

| 要件 | 主な外部仕様 |
| --- | --- |
| `REQ-SCOPE-001` | `EXT-SCOPE-001` |
| `REQ-PROTOCOL-001` | `EXT-TCP-*`, `EXT-UDP-*`, `EXT-DNS-001`, `EXT-PING-001` |
| `REQ-SOURCE-001` | `EXT-ENDPOINT-001` |
| `REQ-DESTINATION-001` | `EXT-CFG-001`, `EXT-RESOLVE-001` |
| `REQ-REPEAT-001`, `REQ-SERVER-001` | `EXT-RUN-001` |
| `REQ-CONFIG-001` | `EXT-CFG-001`, `EXT-CFG-002` |
| `REQ-RESULT-001` | `EXT-RESULT-001` |
| `REQ-NIC-001`, `REQ-NIC-002` | `EXT-NIC-001`, `EXT-NIC-002` |
| `REQ-RUNTIME-001`, `REQ-DISTRIBUTION-001` | `EXT-RUNTIME-001` |
| `REQ-MAINTAIN-001`, `REQ-TESTABILITY-001` | 文書体系、内部設計、受入条件、テスト方針全体 |

要件を変更するときは、最初にこの文書で変更後の要求を確定し、その後に外部設計へ進みます。外部設計、内部設計、ソースコード、テストの現在状態から要件を逆算して後付けしてはいけません。
